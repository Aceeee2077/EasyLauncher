## 使用与验收边界

- RCON 由 Minecraft 自身绑定在所有网络接口上，`server.properties` 无法限制监听地址。应用只连接 `127.0.0.1`，启用时自动生成随机密码并在界面明确提示风险；不会自动添加防火墙规则或端口映射。RCON 命令与控制台 stdin 等价，仍限制为单行、4096 字符。玩家列表解析依赖上游英文 `players online:` 格式，无法识别时明确报错而不伪造结果。
- frp 需要已有服务以及官方安装的 `frpc`。独立配置应只转发需要的 Minecraft 端口。程序以参数数组执行 `frpc -c <配置>`，不调用命令行 shell；运行状态只表示进程存在，不代表隧道已注册成功或公网可连接。应用不保存 frp 凭据内容，不自动开通服务，不集成 playit.gg 账号。停止进程会立即断开对应隧道。
- Aikar 参考 PaperMC 文档；Paper 预设是本项目在 Aikar 参数上的调优变体，不是 Paper 官方独立参数标准。参数效果依赖 Java 版本与实际负载；均衡预设保留 Java 默认策略。自定义项限制为 `-XX:`，拒绝内存、代理、选项文件和启动入口覆盖；启动前再次校验。
- 依赖检查不是完整的加载器解析器。本地读取 Fabric 的 `fabric.mod.json`、Paper 的 `paper-plugin.yml` 与 Bukkit 的 `plugin.yml`（只解析元数据所需的最小 YAML 子集，不执行 JAR）；版本谓词按语义化版本优先级支持比较、通配符、部分版本、波浪线、脱字符、预发布、构建号和 `||` 组合。`fabricloader`、`paper`、`bukkit` 等平台版本无法从内容文件得知，只标记待核对。未托管的 JAR 按 SHA-1 查询 Modrinth，未收录的文件不视为错误；由于远程依赖只带项目 ID，无法映射的项目仍可能显示“未找到托管前置”，需结合本地文件核对。远程查询并发上限为 4、总时限 30 秒、单次最多 128 个 JAR，失败不会伪造完整结果。
- 玩家统计不回填旧日志；只统计本应用观察到的标准英文加入/离开日志。日统计使用 UTC，时间点按界面本地时区展示。保留 30 天日统计、200 条已结束会话与最多 10,000 位玩家；约每 10 秒保存活动时长。异常退出后按最后检查点结算，避免把应用离线时间算成在线时长。
- 日志助手支持 Chat Completions 兼容的完整接口地址，HTTPS 或本机 HTTP；禁用重定向。API Key 默认只在本次请求使用，不写入设置或应用日志；勾选“记住配置”后调用 Windows DPAPI（当前用户作用域，附加固定熵）加密保存到应用数据目录的 `secrets.json`，非 Windows 构建禁用该选项。预览尝试隐藏常见凭据、地址和用户路径，但仍需用户检查。仅发送预览框中实际显示的文本。返回值以纯文本展示，不执行命令。自选模型服务可能收费，本轮没有调用任何外部模型。
- 只读模式由后端 `Manager::ensure_writable` 统一拦截创建、修改、删除、安装、启动、RCON 命令、隧道启动等操作，并返回稳定错误码 `app.readOnly`；停止服务器、停止隧道和退出 Web 控制台始终允许，便于随时降低风险。保存应用设置本身不受限制，否则无法关闭只读模式。
- 审计日志只写本机应用数据目录的 `audit.log`（NDJSON），记录动作、时间、服务器 ID/名称与最多 512 字符的说明；写入为尽力而为，失败不影响原操作，也不会记录密钥内容。超过约 1 MB 轮转为 `audit.1.log`、`audit.2.log`；读取时最新在前，最多 500 条；清空本身会留下一条 `audit.clear` 记录。DPAPI 密钥库同样通过受控存储路径读写，单值上限 16 KiB。
- 手机控制台绑定本机随机端口并展示局域网地址，不做公网穿透；访问令牌通过 URL 片段交付，不进入查询串、Referer 或应用日志；页面用一次性换取的 HttpOnly + SameSite=Strict 会话 Cookie 访问接口，写操作还需 `X-CSRF-Token`。会话 12 小时过期、最多 16 个，登录失败 60 秒内超过 8 次返回 429。响应带 CSP、`no-store`、`nosniff`、`no-referrer`、`DENY` 等头；关闭控制台或退出应用后会话随即失效。
- 后端高频错误带稳定 `code`（如 `server.notInstalled`、`server.javaMismatch`、`network.portInUse`、`backup.noWorld`），界面按当前语言翻译并保留原始信息在详情中；未映射的错误仍直接显示后端原文，不会静默改写。
- 开服体检只读取本地可观测状态，不自动修改系统。防火墙检查仅 Windows 生效，规则缺失计为注意；无法读取规则时只提示。UPnP 未映射计为提示，不扣分、不触发映射；JVM 参数仅在自定义预设下校验，其他预设的附加参数只提示会被忽略。评分满分 100，每项问题扣 25、每项注意扣 8，最低 0。
- 总览页批量操作只对当前状态可接受该操作的服务器生效（已安装且空闲才能启动，安装中与过渡状态跳过），其余已勾选项不报错也不执行；前端并行调用既有命令，仍由服务器级互斥保证同一台不会被并发操作。失败按服务器名与后端原始信息列出，超时或拒绝连接不会被视为成功。
- 分享图片使用本地绘制素材，不包含手机控制台 token。保存位置由后端固定为应用数据目录中的 `share-cards/<随机 UUID>.png`，前端不能指定任意写入路径。图片剪贴板依赖系统与 WebView 支持，失败时可使用保存 PNG。
- 备份比较基于创建时保存的 SHA-256 索引，世界存档之外的配置、模组和插件不在备份内。不要手动修改受控快照内容。差异视图最多展示 500 个变化文件，统计包含全部索引项；仅比较文件内容，不解析 MCA 内部区块。分块备份的 `files.json` 与 manifest 同时写入；索引缺失时优先从 manifest 重建，旧目录快照仍走目录扫描补建。
- 分块备份以 1 MiB 为单位读取世界文件，每个数据块解压后计算 SHA-256，再以 zstd 压缩存入 `backups/chunks/<前两位>/<sha256>.zst`。相同数据块跨备份只存一份；`manifest.json` 记录文件路径、文件级哈希、数据块顺序与未压缩长度。备份记录新增 `format`、`storedBytes`、`chunkCount` 与 `fileCount`，旧记录通过 serde 默认值视为 `directory`。恢复先写入 `restore-<uuid>/new`，逐块校验长度与 SHA-256，全部通过后才执行原有的目录交换；任何缺失或损坏返回 `backup.corrupt`。删除备份与保留策略清理后都会遍历剩余 manifest 回收无引用数据块；无法读取任一 manifest 时中止回收，避免误删仍被引用的块。
- 远程备份把分块快照连同 manifest、文件索引与实际引用的数据块打包为单个 ZIP，可选 age 口令加密，再上传到 WebDAV、S3 兼容存储或本机 rclone。上传暂存文件位于服务器目录的 `remote-backups/staging/`，历史记录在 `remote-backups/history.json`，未完成状态在 `pending.json`；网络传输不持有服务器操作锁，但打包阶段仍要求可写。S3 使用分片上传并记录已完成分片，可在同一目标上续传；WebDAV 没有标准续传，中断后会从头重传；rclone 调用本机进程并使用其自身能力。上传后默认只校验远程大小，启用内容校验时会重新下载并比对 SHA-256。WebDAV 与 S3 的密码/Secret Key、归档口令通过 Windows DPAPI 保存，配置文件只含端点、桶、区域、用户名/Access Key ID 等非秘密字段。当前版本只上传与校验，不能从远程归档直接恢复；HTTP 端点会明文传输凭据和备份内容。
- 保留策略保存在 `backups/retention.json`，默认关闭，默认窗口为 7 日 / 4 周 / 3 月。每组保留最近 N 个时间桶中的最新一份，安全备份、有备注的备份、无法解析日期的备份与全局最新备份永不自动删除。界面先展示候选与预计释放量，确认后才删除；启用后，每次成功的定时备份会自动执行一次，手动备份不会触发。旧目录快照与分块快照可混合保留。
- 在线备份复用本地 RCON 通道，并在整个过程中持有服务器操作锁；`save-off` 成功后无论后续复制是否成功都会尝试 `save-on`（最多 3 次），失败返回 `backup.saveOnFailed`，已完成的备份仍会保留。Minecraft 没有文件系统快照接口，暂停自动保存与强制刷盘只能降低写入风险，复制期间区块卸载等写入仍可能发生；界面与文档不会把它描述为原子快照。RCON 未启用或服务器未运行时直接拒绝，不会退化为后台复制正在写入的世界目录。
- 版本升级在持有服务器操作锁且状态为空闲时执行：先解析上游产物与目标 Java 主版本，缺少运行时直接拒绝；有世界数据时创建带 `before upgrade <version>` 标签的安全备份；下载写入 `server.upgrade.jar`（同目录 `.part` 临时文件），校验通过后再交换 `server.jar` 与 `server.jar.previous`。任一步骤在交换前失败都不会改动现有 JAR；交换后写标记或保存元数据失败会恢复原 JAR。回退只交换 JAR 并恢复旧版本、产物名与 Java 路径，不修改世界；`upgrade.json` 是单步回退指针，缺少 `server.jar.previous` 时视为不可回退。模组与插件不做迁移或兼容性判断，只统计 JAR 数量提示。
- 内容更新只处理 `content.json` 中记录的项目。检查按当前 Minecraft 版本与加载器筛选 Modrinth 版本，优先最新正式版；更新日志最多保留 20,000 字符，依赖影响只列出必需/不兼容声明的增减与变化。钉住项目的版本记录在 `content-pins.json`，不影响手动更新。更新在服务器停止并持有操作锁时执行：下载到内容目录的隐藏临时文件并校验，旧 JAR 复制到 `content-backups/` 并写入 `content-rollback.json` 后才替换；索引写入失败会恢复旧文件。每个项目只保留一份回退记录且只回退一份 JAR，不联动依赖，也不修改世界或配置。回退需要显式确认；缺少保存文件或文件名冲突时明确报错。手动放入的 JAR 不参与检查。
- 计划任务的 cron 只解析五段数字字段，不识别英文名称；日与星期同时限定时取交集。下一次执行按本地时区逐分钟扫描（最多一年），会对夏令时的不存在与重复时刻选择第一个仍晚于当前时间的真实时刻。任务每 20 秒轮询；下次执行时间已过超过 2 分钟时视为应用离线期间错过，按任务策略跳过或只补跑一次，随后总是从当前时间重新计算，不会逐次补跑。前置任务仅在本次轮询中排序：前置失败或未执行时，后继记为“未执行”；前置不在本次到期集合中时不阻塞，手动触发也不校验前置。依赖只允许单个前置且禁止自引用与环。执行历史单独保存到 `task-history.json`，每次触发追加一条并保留最新 200 条；日历只包含启用任务，最多 31 天与 500 条，预览最多 20 次。
- 世界预览只读备份，不写入世界或备份文件：分块快照通过 manifest 逐块重建并校验文件 SHA-256，旧目录快照直接读取；所有路径都经过世界前缀与安全名称校验，并拒绝符号链接/重解析点。区域文件限制 128 MiB、NBT 解压后限制 64 MiB，扫描最多 256 个区域 / 50,000 个区块，损坏条目最多返回 200 条。支持 gzip、zlib 与未压缩区块；1.20.5 起的 LZ4 区块（类型 4）目前会报告为不支持而不是猜测内容。地图颜色按方块名称与高度近似着色，不代表游戏内材质；实体统计来自 `Entities` / `block_entities` 列表。在线轨迹仅由用户点击“采样在线玩家”后通过本机 RCON 读取 `Pos` 与 `Dimension`，写入服务器目录的 `world-tracks.json`，保留 7 天、每人最多 600 点，不发送到网络。玩家坐标来自备份时的 playerdata，并非实时位置。
- 整合包覆盖文件不能覆盖应用的 `player-stats.json`、`tunnel.json`、`modpack.json`、暂存包与回退备份。
- 整合包安装后写入 `modpack.json`，记录受管文件与 overrides 的路径和哈希。检查更新会把候选 `.mrpack` 下载到 `modpack-pending.mrpack`，解析布局后按哈希生成新增、修改、移除与未变列表；`server-overrides/` 覆盖同路径的 `overrides/`，客户端专用、受保护与超限文件会被跳过，受管文件与 overrides 路径冲突时保留 overrides。确认更新只下载哈希变化的受管文件，并复用已存在且哈希匹配的本地文件；被替换或删除的旧文件复制到 `modpack-backups/<uuid>/`，任一写入失败会立即恢复，成功后写入 `modpack-rollback.json` 供一次回退。每台服务器只记录一个整合包，安装另一整合包或其他版本会被拒绝。CurseForge 需要 API Key，当前不支持。
- 服务端软件通过 `server/software.rs` 的 adapter trait 分派：Vanilla 读取 Mojang 清单（含快照，正式版下限 1.7），Paper 结合清单与 v3 `STABLE` 构建（SHA-256），Purpur 使用其 v2 API（只公布 MD5，当前仅依赖 HTTPS 与 ZIP 头校验），Fabric 使用 Fabric Meta 的稳定加载器与安装器。安装器只负责共享的下载、重试、长度与哈希校验。快照只对 Vanilla 与 Fabric 开放；Paper/Purpur 的列表只保留上游存在稳定构建的正式版。Spigot 没有官方产物 API；Forge、NeoForge 与 Quilt 的安装需要执行官方安装器并采用非 `-jar` 启动参数，当前启动模型不支持，因此不提供选项，导入时也不会自动识别为这些类型。Purpur 目录通过 `purpur.yml` 或 JAR 名识别，插件与依赖检查按 Paper 布局处理。

## 真实服务器 E2E

`src-tauri/tests/minecraft_e2e.rs` 是默认忽略的端到端验收用例。它在临时应用目录中下载并运行真实的 Vanilla、Paper 或 Fabric 服务端，验证：安装产物是有效 JAR、EULA 仅在临时目录内接受、日志就绪行触发 `running`、端口接受连接、控制台命令有真实回显、`stop` 干净退出（退出码 0）、备份包含世界、恢复删除备份后的改动并保留安全快照，以及强制终止后自动重启并再次就绪。测试结束删除临时服务器，不接触现有存档或配置。

- 本地运行：`cd src-tauri && cargo test --test minecraft_e2e -- --ignored --nocapture`
- 目标选择：`E2E_SOFTWARE=vanilla|paper|fabric`（默认 `vanilla`），`E2E_MC_VERSION`（默认 `1.21.4`）。
- 需要网络与磁盘空间。应用要求与目标版本完全一致的 Java 主版本；本机没有匹配运行时时，用例会通过现有受管 Java 下载器安装 Temurin（8/17/21/25）。
- `.github/workflows/minecraft-e2e.yml` 仅支持手动触发（`workflow_dispatch`），不会在 push、PR 或定时任务中启动游戏；CI 需要先构建前端资源，`tauri-build` 才能在干净检出中编译。默认测试、日常使用与自动流水线都不会启动真实服务器。
