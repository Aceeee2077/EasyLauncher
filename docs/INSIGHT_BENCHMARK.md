## 入口与使用

1. 打开任一已有服务器 → 运维 → 日志洞察工作台。
2. 选择日志，点击“分析所选日志”；新服务器还没有日志时会显示空状态。
3. 点击事件分类或小时柱，选择玩家或输入关键词；点击“清除筛选”恢复全部事件。
4. 用书签按钮标记需要保留的原始行，可以只看标记并导出 JSON。标记在重新分析、切换日志或离开页面后清除。

## 数据准确性与读取边界

- 只识别标准英文 `Server thread` 服务端消息。插件自定义格式、其他线程输出、多语言死亡文本与未列入规则的事件可能不会被识别。不能用这些统计代替完整的游玩时长、伤害或战斗统计。
- 先识别 `<玩家> 聊天`，再匹配服务端事件，避免聊天内容中的“joined the game”等文本冒充加入事件。
- 事件按源文件顺序展示；时间是日志中的 `HH:mm:ss`，不会猜测日期或转换时区。单文件跨多天时，相同小时合并统计；无效时间不计入小时图。
- 每次最多读取开头解压后 8 MiB，最多保留 10,000 个事件。超限明确提示“结果不完整”，并在 JSON 中写入 `truncated`；字节上限处的不完整行会丢弃。单条证据最多 1,000 个字符。
- 凭据关键词、常见路径和地址使用现有本地基础脱敏规则处理；这是启发式处理，分享前仍应检查导出内容。
- 路径只能来自受管服务器的 `logs/`，复用 UUID、单层文件名、符号链接和 Windows junction 校验；不提供任意路径读取。
- 解压、读取和索引在后台阻塞任务中执行；UI 每页最多渲染 100 条。只读模式同样可用，无日志写入，不连接上游，不启动 Java。

## 本轮验证

- 前端新增 4 个测试，验证组合筛选、时段筛选、标记、实际导出 JSON 只含筛选事件、切换来源清除结果、截断提示与空日志库。
- Rust 新增 6 个测试，验证聊天伪造隔离、事件/玩家/行号、时间与凭据处理、gzip 读取与损坏、解压/事件上限、库排序与遗漏数量、路径拒绝，以及受管服务器只读模式的实际读链路。
- 全套前端测试 18 个通过；Rust 库测试 215 个通过、3 个默认忽略，存储安全集成测试 1 个通过。
- TypeScript、IPC 契约、错误码覆盖、生产构建、包体积预算、Rust 格式、Clippy correctness/suspicious 与全目标编译检查通过。
- 没有启动 Minecraft，没有修改用户服务器、路由器或防火墙；未进行安装后的原生点击回归。Windows 安装包沿用现有 NSIS 配置。

受限环境运行 Rust 测试时，`TEMP` 与 `TMP` 应指向项目内可写临时目录。首次默认系统临时目录运行的权限失败，已在更正临时目录后重跑通过。
